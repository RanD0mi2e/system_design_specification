# 需求分析：云存储产品

## 概述

本文档对类 MEGA 云存储产品进行系统化需求分析，涵盖用户角色定义、功能性需求、非功能性需求及约束条件。目标：构建一个端到端加密的跨平台云存储系统，支持文件管理、同步、共享、多设备协作等核心场景。

---

## 1. 用户角色

| 角色 | 描述 | 核心场景 |
|------|------|----------|
| **匿名用户** | 未注册访客 | 通过共享链接查看/下载文件 |
| **注册用户 (Free)** | 基础存储配额用户 | 上传、管理、分享文件 |
| **付费用户 (Pro)** | 更大存储与带宽 | 大文件上传、团队共享、优先带宽 |
| **团队管理员** | 管理团队成员与共享空间 | 成员权限、审计日志 |
| **系统管理员** | 平台运维 | 监控、告警、用户管理 |

---

## 2. 功能性需求

### FR-1: 用户认证与账户管理

#### FR-1.1 注册
- 系统应支持邮箱+密码注册
- 注册时客户端生成 X25519 密钥对，公钥上传至服务端
- 密码经 Argon2id 本地哈希后派生认证密钥，服务端仅存储 bcrypt(认证密钥)
- 系统应要求密码最少 8 位，包含大小写字母、数字、特殊符号中至少三类
- 系统应发送邮箱验证链接，验证通过后账户激活

#### FR-1.2 登录
- 登录时客户端使用密码派生认证密钥，与服务端 bcrypt 比对
- 登录成功后服务端签发 Ed25519 签名的 JWT，有效期 15 分钟
- 系统应支持 Refresh Token（有效期 30 天）自动续期
- 连续 5 次登录失败锁定账户 15 分钟

#### FR-1.3 会话管理
- 用户应可在"设备管理"页面查看所有活跃会话
- 用户应可远程注销指定设备
- 检测到异常登录（新设备/新地点）应发送邮件通知

#### FR-1.4 密码管理
- 忘记密码：通过邮箱验证码重置。重置后历史加密数据不可恢复（零知识设计）
- 修改密码：重新加密主密钥，非重新加密所有文件

---

### FR-2: 文件管理

#### FR-2.1 上传
- 支持单文件最大 16TB（理论值，实际受配额限制）
- 文件上传前在客户端使用 AES-256-GCM 分块加密（每块 64KB）
- 每文件生成独立随机文件密钥，文件密钥用主密钥公钥加密后存储
- 支持分块上传（4MB/块），断点续传
- 支持并行上传（最多 6 个并发块）
- 上传完成后计算 Merkle Root 并验证完整性
- 支持拖拽上传、文件夹上传

#### FR-2.2 下载
- 支持文件/文件夹下载
- 文件夹下载自动打包为 ZIP（服务端流式打包，不解密内容）
- 下载时客户端分块解密（64KB/块），支持流式播放视频文件
- 支持断点续传下载
- 下载完成后验证 Merkle Root 确认完整性

#### FR-2.3 文件夹管理
- 支持创建/重命名/删除/移动/复制文件夹
- 文件夹树无限层级
- 移动文件夹时递归更新所有子节点路径
- 删除文件夹时标记删除所有子孙节点（回收站机制）

#### FR-2.4 文件预览
- 图片：支持缩略图、全屏预览、幻灯片模式
- 视频：支持流式播放（HLS/DASH），无需等待完整下载
- 文档：支持 PDF、Office 文档在线预览（服务端渲染，不解密文本内容）
- 音频：支持流式播放与播放列表
- 压缩包：支持在线浏览压缩包内容

#### FR-2.5 版本管理
- 文件修改后保留历史版本（默认保留 10 个版本）
- 用户可手动创建命名版本
- 用户可恢复任意历史版本
- 版本间去重存储（内容寻址，相同块不重复存储）
- 超出数量限制的旧版本自动清理

---

### FR-3: 回收站
- 删除的文件/文件夹移入回收站
- 回收站文件保留 30 天
- 用户可在回收站中恢复或永久删除
- 永久删除不会立即清除加密块，标记为待清理任务
- 30 天后系统自动永久删除

---

### FR-4: 文件共享

#### FR-4.1 共享链接
- 用户可生成文件/文件夹的共享链接
- 链接支持配置：密码保护、过期时间、下载次数限制
- 文件夹共享链接支持在线浏览子文件
- 共享链接可随时撤销

#### FR-4.2 加密共享（零知识）
- 文件密钥使用共享接收者的公钥重新加密
- 接收者使用自身私钥解密获取文件密钥
- 服务端无法访问明文文件密钥
- 共享文件夹时，新加入的文件自动加密共享给所有现有接收者

#### FR-4.3 团队空间
- 团队管理员创建团队空间
- 支持成员邀请与角色管理（Owner/Editor/Viewer）
- 团队空间文件继承团队权限
- 成员退出团队后失去对团队空间文件的访问权限

---

### FR-5: 多设备同步

#### FR-5.1 同步机制
- 客户端维护本地文件树的 Merkle Tree 结构
- 定时（默认 30s）或手动触发同步检测
- 比较本地与服务端 Merkle Root 判断变更
- 仅上传/下载变更的块，非完整文件
- 首次同步全量比对，后续增量同步

#### FR-5.2 冲突解决
- 文件冲突采用"最后写入者胜 + 冲突副本"策略
- 冲突文件自动重命名为 `filename (conflict yyyy-MM-dd HH:mm:ss).ext`
- 用户可在"冲突管理"面板手动合并

#### FR-5.3 离线支持
- 标记文件/文件夹为"离线可用"
- 离线时修改内容本地缓存，上线后自动同步
- 离线操作队列容量上限为 500 条或 2GB

---

### FR-6: 存储配额与计费

#### FR-6.1 配额管理
- Free 用户：20GB 存储 / 5GB 单文件上传 / 每月 100GB 下载
- Pro 用户：2TB 存储 / 200GB 单文件上传 / 每月 2TB 下载
- 团队版：10TB 起，按成员数计费
- 配额超限时禁止上传，现有文件不受影响

#### FR-6.2 传输量管理
- 共享文件下载量计入文件所有者传输配额
- 达到 80%/90%/100% 传输限制时分阶段通知
- 可购买额外传输量

---

### FR-7: 通知系统

- 新设备登录通知（邮件）
- 共享文件被访问/下载通知（应用内 + 邮件）
- 存储/传输配额预警通知
- 团队成员变更通知
- 文件过期（回收站清理）通知

---

### FR-8: 管理与运维

#### FR-8.1 后台管理
- 用户管理（查询、禁用、删除）
- 文件审计（违规内容识别）
- 系统监控仪表盘
- 计费与订单管理

#### FR-8.2 合规
- 支持 GDPR 数据导出与账号删除
- 服务端存储的所有用户数据均为加密态
- 日志不包含明文文件内容或文件名（文件名也在客户端加密）

## 3. 非功能性需求

### NFR-1: 安全性

| 指标 | 要求 |
|------|------|
| **数据传输** | TLS 1.3，禁止降级协议 |
| **文件加密** | 客户端 AES-256-GCM，服务端零明文访问 |
| **密钥管理** | 私钥不出客户端，Key Wrapping 交换 |
| **认证** | Ed25519 签名 JWT + Refresh Token 轮转 |
| **前端安全** | CSP 严格策略，禁止 eval，SRI 校验 |
| **渗透测试** | 每季度第三方渗透测试 |

### NFR-2: 性能

| 指标 | 要求 |
|------|------|
| **上传延迟** | 4MB 块上传 P99 < 2s（排除网络延迟） |
| **下载延迟** | 首字节时间 P99 < 500ms |
| **文件列表** | 10,000 文件列表加载 < 1s |
| **搜索** | 文件名搜索 < 300ms |
| **同步检测** | 1,000 文件同步比对 < 2s |

### NFR-3: 可用性

| 指标 | 要求 |
|------|------|
| **系统可用性** | 99.9%（全年停机 < 8.76 小时） |
| **数据持久性** | 99.999999999%（11个9，纠删码保障） |
| **灾难恢复** | RPO < 1 小时，RTO < 4 小时 |

### NFR-4: 可扩展性

| 指标 | 要求 |
|------|------|
| **用户规模** | 支持 1000 万注册用户 |
| **并发上传** | 支持 10,000 并发上传连接 |
| **文件数量** | 单用户支持 100 万文件 |
| **存储扩展** | 水平扩展，支持添加 MinIO 节点至 256 节点 |

## 4. 约束条件

| 类别 | 约束 |
|------|------|
| **浏览器兼容** | Chrome/Firefox/Safari/Edge 最近 3 个大版本 |
| **移动端兼容** | iOS 15+ / Android 8.0+ |
| **法务合规** | GDPR、中国个人信息保护法、服务端不持有加密密钥 |
| **带宽限制** | Free 用户上传限速 5MB/s，Pro 不限速 |
| **文件类型** | 不限制文件类型，前端拒止 .exe/.sh 等可执行文件上传（可配置） |

## 7. 术语表

| 术语 | 定义 |
|------|------|
| **零知识 (Zero-Knowledge)** | 服务端无法访问明文用户数据的架构设计 |
| **主密钥 (Master Key)** | 用户的根密钥对，用于加密/解密所有文件密钥 |
| **文件密钥 (File Key)** | 每个文件独立随机生成的对称密钥 |
| **密钥封装 (Key Wrapping)** | 用公钥加密对称密钥的过程 |
| **Merkle Tree** | 哈希树结构，用于高效验证文件完整性 |
| **分块上传** | 将大文件切分为固定大小块独立上传 |
| **去重存储** | 相同内容块只存储一份 |
